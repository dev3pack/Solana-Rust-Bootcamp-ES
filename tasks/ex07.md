# ex07 — `Result` y `?`

**Objetivo:** reportar fallos esperados sin hacer panic, y propagarlos con el
operador `?`.

## Conceptos

- `Result<T, E>` es `Ok(T)` o `Err(E)`.
- `Ok(())` significa "éxito sin valor".
- Un enum de error personalizado puede llevar datos, como los montos disponible y
  requerido.
- `?` retorna el error de forma anticipada si el resultado es `Err`; si no,
  extrae el valor de `Ok`.
- `?` solo funciona dentro de una función que retorna un `Result` compatible.
- En Solana, un error revierte los cambios de estado de la transacción, pero la
  transacción igual paga su comisión.

## Qué implementar

Abre `src/ex07.rs`. `TransferError` ya está definido.

| Función | Qué debe hacer |
| --- | --- |
| `validate(from, to, amount)` | Rechazar montos de cero y luego las transferencias a uno mismo |
| `transfer(balance, from, to, amount)` | Validar, verificar fondos y retornar el saldo restante |
| `pay(balance, from, to, amount)` | Llamar a `transfer` y propagar con `?` |

El orden de validación importa:

1. `amount == 0` → `ZeroAmount`
2. `from == to` → `SameAccount`
3. `amount > balance` → `InsufficientFunds { available, required }`
4. en cualquier otro caso, `Ok`

## Ejemplo resuelto

```rust
fn half(n: u64) -> Result<u64, String> {
    if n % 2 != 0 {
        return Err(String::from("número impar"));
    }
    Ok(n / 2)
}

fn quarter(n: u64) -> Result<u64, String> {
    let half = half(n)?;
    Ok(half / 2)
}
```

Si `half(n)` retorna `Err`, `quarter` retorna ese mismo error de inmediato. Si
retorna `Ok`, el valor se enlaza a `half` y la ejecución continúa.

## Pistas

- `validate` no necesita el saldo. Solo mira los nombres y el monto.
- En `transfer`, llama `validate(from, to, amount)?;` antes de verificar el
  saldo.
- Retorna `Err(TransferError::InsufficientFunds { available: balance, required: amount })`.
- `pay` puede ser dos líneas: llama `transfer(...)?` y luego retorna
  `Ok(remaining)`.
- No uses `unwrap()` ni `expect()` en estas funciones. Los tests verifican los
  valores de error.

5. `pay` propaga errores y tiene éxito
