# ex08 — Proyecto final: mini banco

**Objetivo:** combinar un struct, `impl`, un historial `Vec<String>` y `Result`
en una pequeña cuenta.

Este es el proyecto final. Solo usa lo que aprendiste de ex01 a ex07.

## Reglas

- **Nada de `HashMap`.** El historial es un `Vec<String>`.
- **Nada de traits.** No agregues un trait `Auditable` ni ningún otro trait.
- **Nada de panics para fallos esperados.** Retorna `Result`.
- Mantén el formato exacto del historial; los tests comparan los strings.

## Qué implementar

Abre `src/ex08.rs`. `BankError` y `BankAccount` ya están definidos.

| Método | Qué debe hacer |
| --- | --- |
| `BankAccount::new(owner)` | Crear una cuenta con cero lamports y un historial vacío |
| `deposit(amount)` | Rechazar cero; sumar lamports; agregar `"deposit <amount>"` |
| `withdraw(amount)` | Rechazar cero y sobregiros; restar lamports; agregar `"withdraw <amount>"` |
| `balance_in_sol()` | Retornar SOL enteros, descartando el residuo |

Las entradas del historial son exactamente:

```text
deposit 500
withdraw 200
```

Usa `format!("deposit {amount}")` y `format!("withdraw {amount}")`. Sin dos
puntos, sin palabras extra. Las entradas van en inglés porque los tests las
comparan tal cual.

## Ejemplo resuelto

```rust
let mut history: Vec<String> = Vec::new();
let amount = 500;
history.push(format!("deposit {amount}"));
assert_eq!(history, vec![String::from("deposit 500")]);
```

`format!` retorna un `String`. El vector es su dueño, así que el historial vive
más que la variable local `amount`.

## Una sesión

```rust
let mut account = BankAccount::new("alice");
account.deposit(500)?;      // saldo 500, historial ["deposit 500"]
account.withdraw(200)?;     // saldo 300, historial ["deposit 500", "withdraw 200"]
account.withdraw(600)?;     // Err(InsufficientFunds { available: 300, required: 600 })
```

Después del retiro fallido, el saldo sigue en 300 y el historial sigue teniendo
dos entradas. Una operación rechazada no cambia nada.

## Pistas

- `new` recibe `&str`; usa `owner.to_string()` para crear el campo con
  ownership.
- `Vec::new()` crea un historial vacío.
- En `deposit`, verifica `amount == 0` primero. Luego suma y haz push.
- En `withdraw`, verifica el cero primero y luego compara `amount` con
  `self.lamports`. Solo modifica el estado después de que pasen ambas
  verificaciones.
- `balance_in_sol` divide entre `1_000_000_000`, igual que en ex05.
- Los tests usan `assert_eq!` sobre `Result`, así que los valores de error y los
  strings del historial deben coincidir exactamente.

## Tests

`cargo test --test ex08`

Hay cuatro tests:

1. una cuenta nueva está vacía
2. un depósito actualiza el saldo y el historial; el cero se rechaza
3. un retiro actualiza el saldo y el historial
4. un sobregiro se rechaza sin cambiar el estado
